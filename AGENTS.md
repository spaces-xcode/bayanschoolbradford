# AGENTS.md

Guidance for AI agents and developers working on the Bayan Arabiya School Bradford website.

## What this project is

A five-page brochure-and-admissions site for a Bradford supplementary school (Arabic, Qur'an, Islamic studies,
ages 4–16, Sundays). There is no database and no authentication — the only dynamic behaviour is two Netlify Forms.

## Architecture

```
src/
├── data/school.ts          # ALL editable content: contact info, levels, strands, fees, terms, FAQ
├── components/
│   ├── SiteHeader.tsx      # Sticky header: contact ribbon, logo, nav, mobile menu
│   ├── SiteFooter.tsx      # Dark footer with contact block
│   ├── ui.tsx              # Lozenge, Divider, SectionHeading, PageHero primitives
│   ├── RegistrationForm.tsx# Netlify form "registration" (admissions)
│   └── ContactForm.tsx     # Netlify form "contact"
├── routes/
│   ├── __root.tsx          # Document shell, fonts, meta, header/footer, 404
│   ├── index.tsx           # Home — composed of local section components
│   ├── about.tsx
│   ├── curriculum.tsx
│   ├── admissions.tsx      # Registration form lives here at #register
│   └── contact.tsx
├── router.tsx
└── styles.css              # Design tokens (@theme) + component classes + motion
public/
├── __forms.html            # Build-time form detection skeleton — DO NOT DELETE
└── images/bayan-logo.png   # Supplied school emblem; used as logo, favicon and OG image
```

Routing is TanStack Start file-based routing; `src/routeTree.gen.ts` is generated by the Vite plugin and should not
be hand-edited.

## Conventions

- **Content lives in `src/data/school.ts`.** Do not hardcode phone numbers, fees, times or level names in
  components. `school.phoneHref` is the `tel:` link; `school.phone` is the display form.
- **Styling is Tailwind 4 utilities plus semantic classes** defined in `styles.css`: `.plate`, `.plate-dark`,
  `.hairline`, `.btn`/`.btn-gold`/`.btn-outline`, `.field`/`.field-label`/`.field-error`, `.eyebrow`, `.lede`,
  `.rule-gold`, `.link-quiet`. Reuse these rather than inventing new one-off styles.
- **Colour tokens only.** `ivory`, `parchment`, `sand`, `sand-deep`, `gold`, `gold-light`, `gold-pale`, `gold-deep`,
  `espresso`, `ink`, `ink-soft`, `muted`. The palette is deliberately one warm family — do not introduce cool
  accents. Never pure black.
- **Type**: `font-display` (Marcellus) for headings, `font-body` (Karla) for text, `font-arabic` (Amiri) for Arabic.
  Arabic text always carries `lang="ar"`, and Arabic-only blocks carry `dir="rtl"`.
- **Motion** is CSS-only: `.rise`, `.unveil`, `.drift`, `.sheen` with `.d1`–`.d6` stagger delays. All of it is
  disabled under `prefers-reduced-motion`. Animate transform/opacity only.
- **Ornament**: the `.pattern-girih` eight-point star lattice and `.arch` pointed-arch radius are the recurring
  motifs; `.grain` sits on `<body>` as a fixed overlay.
- **Section components** for a page are defined as local functions in that route file, below the exported route.
  Only genuinely shared UI is promoted to `src/components/ui.tsx`.
- TypeScript is strict with `noUnusedLocals`/`noUnusedParameters` — unused imports break the build.

## Netlify Forms — non-obvious and easy to break

Two forms are registered: `registration` and `contact`.

1. `public/__forms.html` is what makes them exist. Netlify's build bot scans static HTML, and React-rendered forms
   are invisible to it. **Any field added to a React form must be added to that file**, or Netlify rejects the field.
2. Both components POST to `/__forms.html` (not `/`) with `Content-Type: application/x-www-form-urlencoded`. Posting
   to `/` is intercepted by the SSR handler, which returns 200 while silently dropping the submission.
3. Each form sends a hidden `form-name` and a `subject` field (used for notification email subjects) plus a
   `bot-field` honeypot.
4. Submissions cannot be tested locally — use a deploy preview.

The Netlify Forms feature has already been enabled for this site via the skill's `enable.cjs` script.

## Content caveats

Fee amounts, 2026/27 term dates, teaching times and the venue location are plausible defaults, not confirmed facts
supplied by the school. Staff are referred to by role rather than by name on purpose — do not invent names, parent
testimonials, awards, inspection outcomes or pupil numbers. If the school supplies real values, update
`src/data/school.ts` and the "Placeholders to confirm" note in `README.md`.
